# Pixelfic Design System Rule (Foundations v0.4.0)

Every pixel of the plugin panel comes from the Pixelfic UI Kit in Figma. This rule turns that file into instructions an agent can follow without seeing it. When you build anything new, it must look and behave exactly like the kit, in both themes, at 360 by 640.

The rule has two halves. The mechanical half is enforced by `npm run lint:design` and the token drift check, so a violation fails the gate. The judgement half (which component, which surface, which copy) is enforced by the checklists in sections 2 and 13, and by the `framer-design-system` review agent.

Precedence when they disagree: **Figma, then this rule, then the reference CSS, then feature code.** If Figma moved and the reference did not, update the reference, run `npm run sync:tokens`, and record the change in section 15. Never patch a slice by hand: the provenance diff will fail.

Only the agent's own view of Figma is a screenshot. When a value is read from a screenshot rather than Dev Mode, say so in the change and ask for a Dev Mode check.

## 2. Pre-Flight: Before You Write Any UI

1. Read this file. Then read the kit component you will use in `src/components/ui/` and its classes in `src/styles/components.css` or `kit.css`.
2. Find the Figma page that owns the thing you are building (section 8 table). Build what that page shows, not a variation.
3. If no kit component fits, stop and follow section 9 ("A Component Is Missing"). Do not hand-roll a lookalike in feature CSS.
4. Decide the surface for every box you add, from section 6. Write it down in the dev doc if it is not obvious.
5. Count primary buttons in the view you are touching. The answer must stay exactly one.

### 3.3 Brand (Mode Per Plugin)

| Figma name | CSS variable | Value |
| :--- | :--- | :--- |
| brand/primary | `--px-brand-primary` | #5271FF. Fills, indicators, slider fill. **Never text, never a flat button fill** |
| brand/primary-hover, pressed | `--px-brand-primary-hover`, `-pressed` | #4761DB, #3B51B8 |
| brand/on-primary | `--px-brand-on-primary` | #FFFFFF |
| brand/subtle | `--px-brand-subtle` | Indigo 20%. Icon circles, brand badges, active pills |
| brand/action | `--px-brand-action` | #4761DB. Checked checkbox, toggle on, radio, New badge |
| brand/gradient | `--px-brand-gradient` | 180deg #5271FF to #3B51B8. Primary buttons, logo tiles, tab indicator |

Contrast facts that drive rules: white on the gradient is at least 5.2:1 at the label (AA). White on flat #5271FF is 4.07:1 (fails). #5271FF as text on white is 4.07:1 (fails), so brand text is `--px-color-text-brand` (#4761DB light, #8FA3FF dark).

### 3.4 Legacy Aliases

`--title`, `--paragraph`, `--paragraph-faint`, `--framefic-*`, `--bg-card*`, `--secondary-default` still resolve and existing code may keep them. New code uses the Figma names above. Never use `--secondary-default` as a text colour: the linter rejects it.

## 4. Typography

Inter everywhere, the Framer plugin font. JetBrains Mono for code. Use the `font:` shorthand tokens; pair Title tokens with their tracking token.

| Style | Token | Spec | Use for |
| :--- | :--- | :--- | :--- |
| Title/Large | `--text-title-lg` | Semi Bold 20/26, -2% | Panel and hero titles |
| Title/Medium | `--text-title-md` | Semi Bold 15/22, -1% | Section headings (`.section-title`) |
| Title/Small | `--text-title-sm` | Semi Bold 14/20, -0.5% | Card titles, sheet titles, header plugin name |
| Body/Large | `--text-body-lg` | Regular 14/21 | Longer descriptions, hero tagline |
| Body/Default | `--text-body` | Medium 12/18 | Default plugin text (Framer base) |
| Body/Strong | `--text-body-strong` | Semi Bold 12/18 | Buttons, labels, tabs, row titles |
| Body/Small | `--text-body-sm` | Regular 11/16 | Hints, captions, footer, version |
| Body/Small Strong | `--text-body-sm-strong` | Semi Bold 11/16 | Badges, small labels |
| Mono/Default | `--text-mono` | Regular 12/18 | Formulas, event IDs, code. 11px inside chips |

**Enforced:** font-size is 11, 12, 14, 15, or 20px. Weight is 400, 500, or 600. No uppercase labels: everything is sentence case. No literal font stacks.

## 5. Spacing And Radius

**Spacing** (`--space-N`): 2, 4, 6, 8, 10, 12, 16, 20, 24, 32. Nothing else (1px only for hairline nudges).

| Where | Value |
| :--- | :--- |
| Tab panel padding | 16 |
| Between sections on a tab | 20 (Home) or 24 (dense settings) |
| Section title to its content | 10 |
| Inside a card | 12 to 16 padding, 12 gap |
| Between rows in a list | 8 |
| Field rows | gap 12 inside a row, 8 between rows |

**Radius** (`--radius-N`): 4, 6, 8, 10, 12, 14, 16, 20, full.

| Element | Radius |
| :--- | :--- |
| Code chips, path badges, checkbox | 4 |
| Segment inside a track, small chips | 6 |
| Inputs, selects, Small buttons, icon buttons, inner wells | 8 |
| Medium buttons, logo tiles, small list rows | 10 |
| Data rows (member, tier, step) | 12 |
| Cards, accordion cards, banners, toasts, help tiles | 14 |
| Panels, empty states | 16 |
| Hero card | 20 |
| Pills, badges, dots, avatars, icon circles | full |

## 6. Surfaces And Elevation

The surface ladder from the Foundations "How to use" note. Pick the rung, do not invent one.

| Rung | Fill | Edge | Shadow token | Examples |
| :--- | :--- | :--- | :--- | :--- |
| Panel | bg/default | none | none | Tab content background |
| Raised | bg/raised | 1px border/divider | `--px-shadow-card` | Cards, tiles, rows, hero |
| Raised, hover or open or selected | bg/raised (unchanged) | border/brand | `--px-shadow-card-hover` | Hovered card, open accordion, selected row |
| Popover | bg/raised | 1px border/divider | `--px-shadow-popover` | Toasts, menus, floating lock card |
| Inner well | bg/secondary | 1px border/divider | none | Snippet box, deploy box, table inside a card |
| Control | bg/tertiary | none or divider | none | Inputs, selects, chips, segmented track |
| Selected control | bg/selected | border/selected | soft | Active segment |
| Primary action | brand/gradient | white 12% | `--px-shadow-primary` | `.primary-cta` |

Rules:
- Open or selected never changes the fill to bg/secondary; it changes the edge to border/brand.
- Focus is always the pair: 1px focus/ring plus `--px-focus-halo`. Never a 2px outline, never a different colour.
- Composite tokens (`--px-shadow-*`, `--px-focus-halo`, `--space-*`, `--radius-*`, `--text-*`) are declared on `body`, not `:root`, so they resolve against the active theme.

## 7. Shell And Home Tab

**Window**: `framer.showUI({ position: "top right", width: 360, height: 640 })`. Collapse to height 36 (the tab bar).

**Framer draws its own window bar** above every plugin (plugin name and close), and the SDK cannot hide it. So the plugin draws **no header of its own**: the Figma 48px Plugin header repeated the name and close, and the user dropped it on 2026-10-15.

**Three-part shell** (`<PluginShell>`), Figma Navigation page minus the header:

| Part | Height | Contents |
| :--- | :--- | :--- |
| Tab bar | 36 | Top row. Up to 4 tabs, spacer, then the Account (UserRound) icon button pinned right. Inactive tab text/secondary, active Body/Strong plus 2px gradient pill. Hairline below |
| Content | flex | Scrolls. `.tab-panel` padding 16 |
| Plugin footer | 40 | bg/secondary with a top hairline. `@Framefic` then a brand ArrowUpRight (after the label, not before), version tag right, both text/tertiary Body/Small. Always pinned, never hidden |

Rules:
- **At most 4 tabs.** The Account icon must always be visible; a fifth tab pushed it out of the panel once (`test/tabs.test.ts` guards this).
- **Account icon opens the account view** (Connect). While it is open no tab is selected and the icon shows its pressed fill.
- **Collapse is in Framer's window bar**, left of its close button, as a plugin menu item (`framer.setMenu`: "Collapse panel" / "Expand panel"). It is the only thing a plugin can put in that bar; Framer draws the menu button and items are text only. Put any other panel-level command there too, never in the tab bar.
- Never add a close button: Framer's bar has one. The tab bar holds tabs and Account only.
- Collapsed, only the tab bar renders; picking a tab or Account expands the panel.

**Home tab order** (Figma "Pixelfic shell Home tab"):

1. Banner, only when the screen has a state the user must know (for example not connected).
2. `<HeroCard>`: title (Title/Large), description (Body/Large), optional brand badge and illustration, the tab's one Medium primary button, full width.
3. Quick Start: `.step-row` routes into tabs (MemberFrame's PRD requires a quick-start guide).
4. Help: `<HelpTileRow>` with exactly three `<HelpTile>`: Guide (FileText), Contact us (Mail), Changelog (List).
5. More From Pixelfic: `<PluginCardList>` of sibling plugins only.

## 8. Component Inventory: Use The Kit

Never restyle a kit class from a feature stylesheet, and never rebuild a kit component. If you need it, import it.

| Need | Figma page | Use | Never |
| :--- | :--- | :--- | :--- |
| A button | Actions | `<Button variant size>` | A raw `<button className="primary-cta">` or a new button class |
| An icon-only action | Actions | `<IconButton label>` | A bare svg in a `<button>` |
| A form row | Inputs | `<FieldRows>` + `<FieldRow label htmlFor>` | Label above control in a properties form |
| Explain what a field is for | Kit extension | `<FieldRow hint="...">`: an info icon beside the label with a tooltip (`<InfoTip>`) | A help paragraph under the field. That slot is for errors only |
| Text input | Inputs | `<TextField>` | A styled `<input>` |
| Dropdown | Inputs | `<Select>` | A custom menu |
| On or off, applies instantly | Inputs | `<Toggle>` | A checkbox |
| On or off, needs Save | Inputs | `<Checkbox>` | A toggle |
| Pick one of 2 to 3 views | Inputs | `<Segmented>` | A hand-built tab bar (this happened, see changelog) |
| A number in a range | Inputs | `<Slider>` | A number field alone |
| Status or tier label | Content | `<Badge tone>` | A one-off pill class |
| Home hero | Content | `<HeroCard>` | A custom welcome block |
| Help links | Content | `<HelpTile>` in `<HelpTileRow>` | Help tiles used as in-app shortcuts |
| Sibling plugin promo | Content | `<PluginCard>` in `<PluginCardList>` | Plugin cards for docs or support links |
| Route into a tab | Kit extension | `.step-row` (kit.css) | A help tile or plugin card |
| Titled group in a tab | Kit extension | `.section-group` > `.section-header` > `.section-title` + `.section-subtitle` | A new heading class |
| Identifier in prose | Kit extension | `<code className="code-chip">` | A per-feature code style |
| Action finished | Feedback | `useToast()` | A banner |
| Persistent screen state | Feedback | `<Banner tone>` | A toast, a coloured div |
| Nothing here yet | Feedback | `<EmptyState>` with exactly one action | A blank area |
| A field is wrong | Feedback | Inline message under the field, `aria-describedby` | A banner |

Figma components not yet in the kit: Radio (CSS exists, no React wrapper), AI field, Help card, Illustration/Pro, Icon/Crown, Logo/Calfic. Build them through section 9 when first needed.

## 9. A Component Is Missing

1. Confirm it is really missing: search `src/components/ui/`, `components.css`, `kit.css`, and the Figma page.
2. Add it to the kit, not the feature: React in `src/components/ui/<Name>.tsx`, exported from `index.ts`; CSS in `src/styles/kit.css` using tokens only.
3. If the reference CSS already has its classes, use them. If the reference has them wrong against Figma, fix the reference and run `npm run sync:tokens`.
4. Document it in section 8 of this file and in the feature's dev doc.
5. Then use it from the feature.

## 10. Component Specs

### Actions (Button And Icon Button)

- Sizes: Small 30px radius 8, Medium 36px radius 10. Use Medium for the primary CTA of a view. Label Body/Strong, sentence case.
- Primary: brand gradient + `--px-shadow-primary`. Hover flat brand/primary-hover, pressed brand/primary-pressed. Exactly one per view.
- Secondary: bg/tertiary + hairline. Ghost: transparent, hover bg/tertiary. Danger: status/danger-subtle fill, status/danger text, destructive only, confirm first.
- Icon button: 30 by 30, radius 8, 16px icon, `aria-label` and `title`.
- Disabled: 50% opacity, `aria-disabled`, not reachable by Tab.
- Don't: two primaries in a view; generic labels (OK, Submit, Click here); flat #5271FF fill; an icon button for an unclear action.

### Inputs

- Controls are 30px tall, radius 8, bg/tertiary fill. Field row: label left (Body/Default, text/secondary), control right (160px or `.fill`), min-height 30.
- States: Default, Hover, Focus (1px focus/ring + Focus/Halo), Error (1px status/danger + message below), Disabled (50%).
- Checked checkbox, toggle on, and radio fill with brand/action. Toggle 28 by 16. Checkbox 16, radius 4.
- Segmented: 30px track bg/tertiary, active segment bg/selected + border/selected.
- Slider: track control/track, fill brand/primary, white knob, value chip on bg/tertiary.
- Don't: placeholder as the only label; toggle for options that need Save; colour alone for errors.

### Navigation

- Covered by section 7. Tabs: `role="tablist"`, `aria-selected`, arrow keys. Footer link `aria-label` says it opens the browser.

### Content

- Help tile: bg/raised, radius 14, hairline, Shadow/Card; icon in a 32px brand/subtle circle with text/brand glyph. Hover border/brand + lift.
- Plugin card: bg/raised, radius 14, 44px gradient logo tile, Title/Small name, Body/Default description, open arrow on a bg/tertiary square.
- Badge: 18px tall, radius full, Body/Small Strong. 1 to 2 words, never clickable, pairs at least 4.5:1.

### Feedback

| Situation | Use |
| :--- | :--- |
| Action finished | Toast: 45 characters max, optional Undo, at least 5s, pauses on hover and focus. `role="status"`, error `role="alert"` |
| Screen has a state the user must know | Banner: Info, Success, Warning, Danger. Radius 14. Danger `role="alert"`. Max 2 per screen |
| Area has no content | Empty state: radius 16, dashed hairline, 40px icon tile, exactly one next step |
| Field input wrong | Inline message under the field |

Don't: toast for errors that need a decision; more than 2 banners; blank areas; colour as the only signal.

## 11. Accessibility

- Both themes hit WCAG AA for text (4.5:1) and controls (3:1). text/tertiary is not essential text.
- Every control has a visible, linked label. Icon-only controls have `aria-label` plus `title`.
- Keyboard focus is visible on every interactive element, using the focus pair from section 6.
- Targets: 30px Framer default meets WCAG 2.2 (24px minimum). Use Medium 36 for primary CTAs.
- Cards and tiles that open the browser say so in their accessible name.

---

## 12. Copy

- Buttons: verb plus object, 2 to 4 words, 25 characters or fewer, sentence case. Leading icon as the verb cue: Plus for add or insert, Sparkles for AI.
- Labels, badges, tabs, table headers: sentence case. Never uppercase.
- No emoji, no typed bullets or arrows as icons (use a list or a Lucide icon), no en-dash or em-dash anywhere.
- Never show raw enum values (`past_due` becomes "Payment failed").
- Icons: Lucide React or Framer SVG only, `stroke="currentColor"`, sized by CSS (16px in buttons, 14 to 16 elsewhere).

## 13. Post-Flight: Before You Finish

Run, in order, and all must pass:

```
npm run lint:css && npm run lint:design && npx tsc --noEmit && npm test && npm run build
```

If you edited the reference CSS, run `npm run sync:tokens` first; it regenerates the slices and proves zero drift.

Then self-review against this list, and say in your report which items you checked:

- [ ] Every new box sits on a rung from section 6.
- [ ] Every interactive element came from section 8 or was added through section 9.
- [ ] Exactly one primary button in each view you touched.
- [ ] Both themes: no token used that only makes sense in one.
- [ ] Copy follows section 12.
- [ ] Buttons with more than one text line set `height: auto` (see section 14, framer.css).

**You cannot see rendered pixels.** State plainly that light and dark rendering, contrast, and layout at 360px need a human check in Framer, and record it in section 7 of the dev doc.

## 14. Known Gotchas And Open Conflicts

- **framer.css styles every `<button>`**: `height: 30px`, `width: 134px` (reset globally in `shell.css`), `flex-shrink: 0`, `overflow: hidden`. A multi-line button row must set `height: auto` or its text is clipped.
- **framer.css styles every `<input>` and `<select>`** at width 134. Kit controls override it; a raw input will not.
- **Canvas code components are out of scope here.** They render on the creator's published site and follow `references/canvas-component-template.md`, not the panel tokens. Their own contract is the shared appearance block (Theme default Light, Colors, Typography, Layout, Labels, fixed size): see `.claude/agents/framer-canvas-codegen.md`.
- **framer.css is imported into a cascade layer** (`src/styles/framer-base.css`). Its `button:hover, button:focus` rule (specificity 0,1,1) used to beat single kit classes and paint grey pills on focused tabs and rows. Never import `framer-plugin/framer.css` directly.
- **Write CSS files atomically.** A truncate-then-write (`> file`) lets a running Vite dev server cache an empty stylesheet; every token vanishes until the file changes again. The sync script renames from a `.tmp` file. Symptom to recognise: components look right (they have fallbacks) but every kit.css surface is unstyled.
- **Resolved: tabs.** Was conflict C26 (five tabs). The user chose 4 tabs with Connect behind the Account icon on 2026-10-15. Never re-split Manage.
- **Resolved: header.** The Figma Plugin header is not built (see section 7).
- **Open: heading case.** Figma section headings are sentence case ("More from Pixelfic"); `instruction/INSTRUCTION.md` says Title Case for headings. The code follows the writing rule until the user decides.
