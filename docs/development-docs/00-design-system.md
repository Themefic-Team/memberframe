# Feature: Design System Alignment To Foundations v0.4.0

Technical record of moving the MemberFrame panel onto the Pixelfic UI Kit Foundations v0.4.0, the rule that keeps it there, and what still needs a human eye.

**PRD reference**: [section 7](../memberframe-complete-prd.md), no F number
**Status**: in progress (awaiting review and human verification)
**Tasks**: cross-cutting, no ledger row. Binding rule: [`.agents/rules/design-system.md`](../../.agents/rules/design-system.md)

---

## 1. Overview and Problem Solved

- **Feature Name**: Design system alignment
- **Target Audience**: Framer Creator (every panel screen)
- **Value Proposition**: The panel had drifted from the Figma kit in ways a creator sees at once: a dark theme one version old (#201F1F instead of Framer's #101010), cards painted the same colour as the panel so they vanished, an invisible selected segment in dark, type sizes off the scale, brand text failing AA, light-mode-only bugs from tokens that did not exist, and kit components rebuilt by hand per feature. This brings every screen back to the kit and adds a gate so it stays there.
- **Priority Tier**: P0: Core MVP

---

## 2. User Flows

### 2.1. In-Plugin Configuration Flow (Framer Designer)

No flow changes. Every tab keeps its behaviour. What changed is what the creator sees:

- **Home**: Hero card, Quick Start step rows, Help tiles (Guide, Contact us, Changelog), More From Pixelfic plugin cards, in the Figma order. The quick-start routes moved off the Help tiles, which the Content doc reserves for help links.
- **Manage**: filter pills size to their label instead of 134px each; member and tier rows no longer clip their third text line.
- **Settings, Page Locks**: the method switch is the kit Segmented control; the Route Shield section has a title; copy follows the content rules.
- **All tabs**: cards on bg/raised with hairline and Shadow/Card, focus is focus/ring plus Focus/Halo everywhere, checked controls in brand/action.

### 2.2. Visitor / Member Runtime Flow

None. Canvas code components are untouched.

### 3.2. Round 2: Shell, Header, Footer (2026-10-15)

Compared against the Figma Home tab by pixel sampling, then decided with the user:

| Issue | Cause | Fix |
| :--- | :--- | :--- |
| Two title bars | Framer always draws a window bar (name, close) the SDK cannot hide; our 48px header repeated it | Header removed (user choice). Collapse moved into the tab bar. Collapsed height 36 |
| Account icon missing | Five tabs measured 313px and pushed it out of 360px | Four tabs; Connect opens from the Account icon (user choice, resolves C26). `test/tabs.test.ts` caps tabs at 4 |
| Grey pill on a clicked tab, rows turning grey | framer.css `button:hover, button:focus` (0,1,1) beat single kit classes | framer.css imported into `@layer framer` via `src/styles/framer-base.css` |
| Every kit surface unstyled in dev | The sync script truncated then wrote; Vite cached an empty `design-tokens.css` | Atomic writes (tmp then rename). Verified the dev server serves all 13,728 bytes |
| Divider under the header | Reference had one; Figma has none | Removed |
| Inactive tabs too faint | text/tertiary instead of text/secondary (#5C6670 sampled) | text/secondary |
| Collapse icon in the tab bar | User asked for it in the top bar, left of close | `framer.setMenu` item in Framer's window bar; tab-bar icon removed |
| Footer | Icon before the label, no handle | `@Framefic` then brand ArrowUpRight |
| Hero glow | Reference aurora; Figma hero is a plain raised card | Removed |
